# Decision de R11 - Medicion de rendimiento

## Responsable y alcance

Daniel Rincon ensambla la infraestructura; cada autor responde por la
complejidad esperada de su operacion. Todo vive fuera de `motor/`:

- `rendimiento/generar.py`: redes sinteticas y llegadas para R10.
- `rendimiento/medir.py`: escenarios, cronometro y salida para terminal, JSON
  y panel web.
- `frontend/src/components/rendimiento/`: panel que muestra los resultados.

## Como medir

```cmd
.\.venv\Scripts\python.exe -m rendimiento.medir
.\.venv\Scripts\python.exe -m rendimiento.medir --tamanos 10000 20000 --solo R10 --json resultados.json
```

Por defecto mide en 10 000, 20 000, 40 000 y 80 000 estaciones con 5
repeticiones. En la web se usa el panel: `iniciar.py` arranca el servidor con
`medir=medir_api`.

## Redes sinteticas

`generar_red(carpeta, estaciones, rutas, paradas_por_ruta, buses_por_parada,
semilla)` escribe los tres CSV del curso con encabezados exactos. Nombres
inventados (`EST 000001`, `R0001`) para no confundirlos con la red real; cada
estacion aparece como maximo una vez por ruta; horas `HH:MM` que admiten mas de
23; filas mezcladas porque el motor no debe suponer orden. Con la misma
semilla el resultado es identico, asi se comparan ensayos. En las mediciones,
una red de n estaciones tiene n/20 rutas de 20 paradas y 4 buses por parada.

## Metodo

- Se separan carga, preparacion, calentamiento y operacion. Solo la operacion
  entra en el tiempo (`time.perf_counter_ns`).
- Se carga una red por tamano y la comparten los escenarios. La carga misma se
  mide aparte (escenario `Red(carpeta)`).
- Repeticiones y mediana; tambien se guardan minimo y maximo.
- Las operaciones que cambian la red se restauran fuera del tiempo medido: tras
  `cerrar` se reabre, tras `agregar_parada` se quita, tras `deshacer` se rehace.
  Asi no se miden miles de cierres de una estacion que ya quedo cerrada. Al
  terminar cada escenario se limpia lo que hizo su preparacion.
- No se mide la red HTTP: Python llama al motor directamente.
- La medicion es en cache caliente (despues del calentamiento) y asi se indica.
- R5 se comprueba funcionalmente y su tiempo se etiqueta aparte.

## Escenarios

| Requisito | Operacion | n | k |
| --- | --- | --- | --- |
| carga | `Red(carpeta)` | estaciones | - |
| R1 | `estado` | estaciones | - |
| R2 | `autocompletar` | estaciones | 10 |
| R3 | `rango` de unos 100 nombres | estaciones | 100 |
| R4 | `proximo_bus` | estaciones | - |
| R5 | `viaje` (funcional) | estaciones | - |
| R6 | `ranking` | estaciones | 10 |
| R7 | `recorrido`, al reves, `agregar_parada`, `quitar_parada` | estaciones | - |
| R8 | `cerrar`, `reabrir` | estaciones | - |
| R9 | deshacer y rehacer un cierre | estaciones | - |

Los que dependen de `motor.Red` aparecen como `pendiente: falta motor.Red`
hasta que se integre; se activan sin cambiar codigo. La complejidad esperada se
toma de la decision de cada autor; donde aun no la hay, el panel lo dice.

## Formato JSON del panel

`POST /api/rendimiento` recibe `{"tamanos": [10000, 20000], "repeticiones": 3}`
y responde `{"ok": true, "datos": filas}`. Cada fila medida tiene:

| Campo | Significado |
| --- | --- |
| `operacion`, `requisito` | Que se midio |
| `estado` | `"medido"`, `"pendiente: ..."` o `"error: ..."` |
| `n`, `unidad`, `k` | Tamano, que significa n y parametro de salida (o `null`) |
| `repeticiones` | Cuantas veces se cronometro |
| `mediana_ns`, `min_ns`, `max_ns` | Tiempos en nanosegundos |
| `relacion` | Mediana dividida por la del tamano anterior (`null` en el primero) |
| `tamano_salida` | Largo de la respuesta si es lista (`null` si no) |
| `cache` | `"caliente (tras calentamiento)"` |
| `esperado`, `nota` | Complejidad del autor y aclaraciones |

Las filas pendientes solo traen `operacion`, `requisito`, `estado`, `esperado`
y `nota`. Limites por peticion (`medir_api`): de 1 a 5 tamanos entre 1 y
100 000, y de 1 a 9 repeticiones, para que una peticion no bloquee el servidor
por demasiado tiempo. Con 80 000 estaciones puede tardar varios minutos.

## Lectura de resultados

Se compara la mediana de n con la de 2n. Cerca de 1: costo constante o
logaritmico. Cerca de 2: lineal (o n log n, que da algo mas de 2). Mas de 2,6:
mas que lineal. No se prometen relaciones exactas: con tiempos de pocos
microsegundos el ruido del sistema pesa mas que el tamano, y el panel lo avisa.
