# R2 — Autocompletar estaciones abiertas

Mariana implementó el ordenamiento merge sort, búsqueda binaria y primera
versión de autocompletado en el PR #27. Catalina conserva esos commits y
completa el índice de estaciones abiertas para evitar recorrer cierres.

Las claves se normalizan con la misma regla de R1. Los resultados conservan
el texto original del CSV. La lista de claves se ordena una vez mediante el
merge sort de Mariana. La búsqueda binaria localiza el inicio del prefijo.

Un AVL propio contiene solo estaciones abiertas, con la clave normalizada
y el nombre original. Desde el límite hallado se recorre en orden hasta k
resultados o hasta que la clave deja de comenzar por el prefijo. Cerrar elimina
la clave del AVL y reabrir la inserta. El registro de R1 sigue siendo la única
fuente del estado; la fachada mantiene también el índice de ranking.

Con n estaciones y k resultados, la construcción cuesta O(n log n) y espacio
O(n). La consulta cuesta O(log n + k), considerando comparaciones de nombres
de longitud acotada. Cambiar el estado cuesta O(log n), además de la búsqueda
hash esperada O(1). El recorrido iterativo evita propagar cada resultado por
una cadena de generadores recursivos.

La alternativa inicial de saltar cerradas en el arreglo era más simple, pero
podía recorrer O(n) estaciones cerradas aun pidiendo un solo resultado. Un
trie permite buscar por longitud del prefijo con mayor cantidad de nodos.
El AVL acota la altura y se comparte con rangos y ranking.

Prefijo vacío devuelve las primeras k abiertas. k <= 0 devuelve []; bool y
tipos incompatibles producen TypeError. La Ñ se conserva y se ordena por el
valor de los caracteres de la clave normalizada, igual que el código de R1.
Las pruebas cubren cierres consecutivos, reaperturas, nombres originales,
acentos, prefijos y límites. Se mantienen las pruebas originales de Mariana.
