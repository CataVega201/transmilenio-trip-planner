# R1: estado de una estación

## Responsable y comportamiento

Responsable: Mariana Parra. Issue:#10 

`IndiceEstaciones(nombres)` guarda cada estación. Ofrece:

- `estado(nombre)`: devuelve `"ABIERTA"`, `"CERRADA"` o `"NO EXISTE"`.
- `cambiar_estado(nombre, abierta)`: devuelve `True` si el estado cambió y
  `False` si la estación no existe o ya estaba en ese estado.

Todas las estaciones empiezan abiertas. Buscar con `portal norte`,
`Portal Norte` o `PORTAL NORTE` da el mismo resultado.


## Cómo funciona



clave: es la clave que usa la tabla hash, se guarda el nombre de la estacion con los filtros de normalizar_
valor: se guarda un registro _Estacion con 2 campos, el nombre original y un booleano abierta.
_normalizar: Quita los espacios de los extremos, pasa a mayúsculas y
  cambia las vocales con tilde y la `Ü` por su letra simple. La `Ñ` se
  conserva.
`estado` normaliza el nombre y busca en la tabla: si no hay registro devuelve
`"NO EXISTE"`; si lo hay, devuelve `"ABIERTA"` o `"CERRADA"` según `abierta`.


## Decisiones

- **Nombre original frente a normalizado.** Se guarda el nombre original y el normalizado solo sirve de clave, porque debe devolverse el nombre exactamente igual al CSV, por eso se guarda el original para mostrarlo y el normalizado es solo para hacer busquedas.

- **Cerrada no es lo mismo que ausente.** Una estacion cerrada sigue existiendo y en cualquier momento puede reabrir, el cambiar_estado devuelve True. Una ausente no existe y cambiar_estado devuelve False para todo. Además se decidio que las cerradas no salgan en autocompletar, rango ni ranking, pero que sigan existiendo para el resto de la red.

## Alternativa

Otra forma sería guardar dos listas, una con las estaciones abiertas y otra
con las cerradas. Para cerrar una estación habría que buscarla en la primera
lista (recorriéndola, porque `x in lista` está prohibido en `motor/`),
quitarla y añadirla a la segunda, y eso cuesta O(n). Con un registro que
tiene un campo `abierta`, cerrar es buscar por clave en la tabla y cambiar un
booleano, sin mover nada. Con 80.000 estaciones la diferencia se nota.

## Complejidad (Big O)

n = número de estaciones. L = longitud de un nombre (pequeña, se toma como
constante).

| Operación | Caso promedio | Peor caso | Por qué |
|---|---|---|---|
| `_normalizar` | O(L) | O(L) | Recorre el texto una vez por `strip`, `upper` y cada `replace` |
| `estado` | O(1) | O(n) | Una búsqueda en la tabla; el peor caso es que todas las claves colisionen |
| `cambiar_estado` | O(1) | O(n) | Una búsqueda y el cambio de un booleano |
| Construcción | O(n) | O(n²) | Guarda n estaciones; cada `guardar` es O(1) en promedio |

## Variables

- `_tabla`: la `TablaHash` que guarda las estaciones. La clave es el nombre
  normalizado y el valor es un `_Estacion`.
- `_Estacion.nombre`: el nombre original, tal como viene en el CSV.
- `_Estacion.abierta`: booleano que indica si la estación está abierta.
  Empieza en `True`.

## Límites

- Si llegan nombres repetidos, queda el último, porque `guardar` reemplaza el
  valor. Validar duplicados le toca a quien carga los CSV.
- `_normalizar` solo cambia las vocales con tilde y la `Ü`. La `Ñ` se
  conserva, y otros caracteres (como `Ç`) no se tocan.
- Si `nombre` no es un texto, por ejemplo `estado(5)`, falla con
  `AttributeError` y no con `TypeError`.
- Una estación cerrada sigue en la tabla; solo cambia su campo `abierta`.
