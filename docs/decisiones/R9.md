# Decisión de R9 — Deshacer y rehacer

## Responsable y comportamiento

Alejandro Curtidor. R9 deshace y rehace los cambios de la red: cierres,
reaperturas y ediciones de rutas. Reglas según [CONTRATOS.md](../CONTRATOS.md),
sección 3 (decisiones del equipo).

```text
cerrar("A")      -> True     A cerrada
cerrar("A")      -> False    sin efecto: no se registra nada
quitar_parada("R1", "B") -> True
deshacer()       -> True     B vuelve a su posición en R1
deshacer()       -> True     A abierta
deshacer()       -> False    no queda nada
rehacer()        -> True     A cerrada otra vez
cerrar("C")      -> True     cambio nuevo: ya no se puede rehacer el quitar
rehacer()        -> False
```

Solo un cambio exitoso genera una acción. Consultar, fallar o cargar no genera
ninguna. Un cambio nuevo exitoso vacía rehacer; uno sin efecto no lo vacía.

## Estructura y algoritmo

`motor/historial.py`. **Dos pilas enlazadas propias** (`Pila`): acciones por
deshacer y acciones por rehacer.

- `registrar(accion)`: apila en «por deshacer» y vacía «por rehacer».
- `deshacer()`: saca la más reciente, la pasa a «por rehacer» y la devuelve.
- `rehacer()`: el movimiento contrario.

El historial no aplica cambios; solo decide cuál toca. `Red` arma la acción con
lo mínimo para invertir el cambio exacto:

| Acción | Datos guardados | Inversa |
| --- | --- | --- |
| `[CERRAR, nombre]` | Estación | Reabrir |
| `[REABRIR, nombre]` | Estación | Cerrar |
| `[AGREGAR, ruta, nueva, despues_de]` | Ruta, parada y referencia | Quitar `nueva` |
| `[QUITAR, ruta, estacion, anterior]` | Ruta, parada y la que tenía antes (`None` si era la primera) | Reinsertar después de `anterior`, o al inicio |

Al deshacer o rehacer, `Red` llama a sus métodos internos de aplicación, que
actualizan recorrido, pertenencia, conteos e invalidan el ranking, pero **no
registran**. Así no se llama al método público de forma recursiva ni se
duplica la acción. Como las acciones se deshacen en orden inverso exacto, la
parada `anterior` guardada siempre está en la ruta cuando toca reinsertar.

## Alternativa descartada

**Copia completa de la red por cada cambio** (lista de instantáneas con un
cursor). Es simple, pero cada cierre costaría O(E + P + H) en tiempo y memoria
(estaciones, paradas y horarios) solo para guardar un bit que cambió. Con
acciones inversas cada registro ocupa O(1).

También se descartó **una sola lista con cursor**: vaciar rehacer exige cortar
la lista y, con arreglos de Python, borrar la cola es O(acciones descartadas).
Con la segunda pila enlazada, vaciar es soltar una referencia: O(1).

## Complejidad

A = acciones guardadas. R = rutas que pasan por la estación editada.

| Operación | Tiempo | Espacio |
| --- | --- | --- |
| `registrar` | O(1) peor caso (incluye vaciar rehacer) | O(1) por acción |
| `deshacer` / `rehacer` en el historial | O(1) peor caso | — |
| Aplicar la inversa de un cierre o reapertura | Lo que cueste `cambiar_estado` de Mariana | — |
| Aplicar la inversa de una edición de ruta | O(1) esperado al insertar, O(R) al quitar | — |
| Historial completo | — | O(A) |

Las pilas son enlazadas: no hay redimensionamientos. El ranking no se
reconstruye al deshacer; solo se marca como desactualizado (ver R8).

## Mediciones

Medición preliminar fuera del panel (Python 3.13, Linux, mediana de 7
repeticiones). Crece A. Cada corrida registra A acciones, las deshace todas y
las rehace todas.

| A | Tiempo por operación |
| --- | --- |
| 100 000 | 249 ns |
| 200 000 | 226 ns |
| 400 000 | 257 ns |

El costo por operación no crece con A, como se espera de O(1). Falta medir en
el panel R11 el costo completo de deshacer sobre la red real, que incluye el
mantenimiento de índices.
